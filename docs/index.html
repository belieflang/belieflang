An experiment in explicit state

BeliefLang

An experimental language and runtime for structured beliefs, uncertainty, and decision-making in AI agents.

AI agents already support memory and state. BeliefLang explores making beliefs, uncertainty, provenance (where information came from), and decision rules explicit.

The goal is to keep structured belief state, update it as new information arrives, and use deterministic code when another LLM call isn't needed. A smaller snapshot can also lose details that matter later.

A small working program

A belief, a threshold, an action

belief intent exclusive closed {
  book_flight: 0.82
  book_hotel: 0.12
  unknown: 0.06
}

when confidence(intent.book_flight) > 0.7:
  call search_flights()

belief declares scores; exclusive closed normalizes them into a full distribution. confidence() reads a stored score.

when checks the condition and runs one action. Here, 0.82 exceeds 0.7, so the local demo calls search_flights().

What the experiments demonstrated

The latest audited GPT-6 Luna pilot compared memory strategies. These totals include all cases under sparse and dense demand, with updates, routing, and retrieval charged.

One repetition · three scripted 24-turn conversations
Approach Accuracy Estimated LLM cost
Full history 89.22% $0.00598334
Rolling summary 91.18% $0.01089550
Plain JSON 100% $0.00440132
BeliefLang v3 100% $0.00440352

Structured state reduced estimated LLM costs by 26.4% versus full-history retrieval and 59.6% versus rolling summaries in this pilot. Plain JSON and BeliefLang v3 performed essentially identically. The measured benefit came from structured state and deterministic processing, not the language syntax.

These 100% scores are not proof of general reliability or production savings. This was one repetition over three authored conversations. Costs use frozen rates with a 10% premium assumption, not invoice charges.

Language and runtime, with different roles

The .bel language

The interpreter supports belief distributions, confidence and entropy, conditional rules, variables, tool calls, observations, inference, and merging updates.

Language reference →

TypeScript runtime components

The runtime provides belief snapshots and provenance APIs. Opt-in v3 components add typed factual updates, source-tracked history, conflict and uncertainty handling, and deterministic decision guards. These are TypeScript APIs, not new .bel syntax.

Runtime and trust boundaries →

Model confidence does not verify a fact or authorize a tool. Guards depend on trusted host evidence and approvals. V3 change history is bounded, durable state can grow, and automatic archival is not implemented.

General dependency tracking, selective invalidation, and more advanced caching are research directions. The pilot's fixed decision cache does not provide complete dependency-based recomputation.

Outside the browser

Run locally or read further

Use Node.js 22 or later. This example uses local demo tools and needs no API key: 

git clone https://github.com/belieflang/belieflang.git
cd belieflang
npm ci
npm run build
node dist/src/cli.js run examples/intent.bel --trace

Open research questions

What comes next?

  • Compare longer conversations and cheaper-model updates fairly with optimized JSON and full-history baselines.
  • Investigate dependency tracking, selective invalidation, and caching before treating them as capabilities.
  • Decide whether a separate language adds enough value. The project may eventually focus on a TypeScript library.
