Beliefs → decisions

Make a decision, then call a tool

BeliefLang keeps the scores your workflow needs. A model updates them from new input. Rules use those scores to choose an action.

new message → belief snapshot → threshold rule → tool call

Each turn starts from the saved snapshot, so the model can update the decision state without reading every earlier message again.

Use a score to make a decision

The model estimates a score. The rule is deterministic: the same score and threshold produce the same tool call.

when confidence(intent.book_flight) > 0.9:
  call search_flights()

Settle each field separately

Choose a confidence threshold for each decision field. When its current value is certain enough, save it and omit that field from the next update. Keep updating uncertain fields. Reopen a settled field when new input could change it.

intent = book_flight (0.97) → settled
prefers_direct = uncertain (0.58) → update next turn

In a separate gpt-6-luna test, settled fields matched 20/20 labeled turns twice and used about 10% fewer tokens: 5,828 vs 6,494, then 5,809 vs 6,458. At a 0.90 threshold, 54 of 60 numeric field updates were omitted. See the method and limits.

Language basics

Define beliefs, then act when a score passes a threshold:

belief intent exclusive closed {
  book_flight: 0.82
  book_hotel: 0.12
  unknown: 0.06
}

when confidence(intent.book_flight) > 0.7:
  call search_flights()

belief

Stores scores. exclusive means one main answer; multi allows several independent scores.

when

Checks a condition and runs one action. Use confidence(...) for a score and entropy(...) for uncertainty.

observe and infer

Record new input and ask an inference adapter to update beliefs. merge applies a belief patch.

See the full language reference for syntax and behavior.

Runtime API

Read state with getState() or confidence(path). Save and restore it with getBeliefSnapshot() and loadBeliefSnapshot(). Inspect decisions with getProvenance(), explainBelief(path), and --trace.

BeliefLang can infer with GPT or Jev. The integration and benchmark notes explain both adapters.

BeliefLang is experimental. Test decision quality on your own workflows before using it to call tools.
