A small language experiment

BeliefLang

Your trip budget changed from $1,500 to $1,200. Your AI agent needs to keep up.

BeliefLang keeps track of what an agent believes and how confident it is. A belief is something the agent currently thinks is true. Uncertainty means it may be wrong.

New information can update those stored beliefs. Regular code can then handle decisions, such as checking a price against your new budget, without asking a language model again.

Agents already have memory. We're testing whether a dedicated language helps more than an ordinary library.

A small working program

Search for flights when confidence is high enough 

belief intent exclusive closed {
  book_flight: 0.82
  book_hotel: 0.12
  unknown: 0.06
}

when confidence(intent.book_flight) > 0.7:
  call search_flights()

Here, belief intent stores what the agent thinks you want to do: book a flight, book a hotel, or something unknown. The scores add up to 1.

confidence() reads the stored score. when checks it against a threshold. Here, 0.82 is above 0.7, so the demo calls search_flights().

Results · October 2026

A small test of conversation memory

We compared four ways to remember a conversation: send the full chat history to the model, keep a running summary, or store selected information in JSON or BeliefLang.

One run · three scripted conversations · 24 turns each
Approach Accuracy Estimated model cost
Full history 89.22% $0.00598334
Rolling summary 91.18% $0.01089550
Plain JSON 100% $0.00440132
BeliefLang v3 100% $0.00440352

Storing selected information and using regular code cut estimated model costs by 26.4% versus full history and 59.6% versus rolling summaries in this test. Plain JSON and BeliefLang v3 performed essentially identically. The savings came from how information was stored and processed, not the language syntax.

The 100% scores apply only to this small test. They do not promise reliability or savings in a real application.

How to read these numbers

The test used GPT-6 Luna. Totals include updating memory and answering questions, under both frequent and occasional use. Costs use the experiment's fixed rates with a 10% premium assumption. They are estimates, not invoice charges.

What you can use today

Write rules in .bel

Store possible answers with confidence scores. Use when rules to call a function, such as a flight search, or ask a question. Read new input and update stored scores.

Language reference →

Keep a record in TypeScript

Keep the current budget, its earlier values, and the message behind each change. That's provenance: where information came from. Mark conflicting information and check evidence or approval before allowing an action.

Memory and action checks →

These extra memory and action checks are TypeScript APIs. They are not part of the .bel syntax or browser demo.

A confidence score isn't proof. Your application still has to verify facts and give permission for actions. Saving less information can also mean losing details you'll need later.

Technical details and current limits

The language supports probability distributions, confidence, entropy (a measure of uncertainty), variables, conditions, tool calls, observations, inference, and merging updates.

The TypeScript runtime has snapshot and provenance APIs. Optional v3 components add factual memory, conflict handling, and deterministic decision guards. Change history is bounded; saved state can still grow, and automatic archival is not built.

General dependency tracking, selective invalidation, and more advanced caching remain research directions. The pilot's fixed decision cache does not provide complete dependency-based recomputation.

cd belieflang
npm ci
npm run build
